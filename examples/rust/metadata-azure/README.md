# SSRF vers le service de métadonnées Azure (IMDS)

`vulnerable.rs` laisse l'utilisateur définir librement l'URL et les en-têtes HTTP d'une requête sortante, ce qui permet, sur une ressource Azure avec identité managée, d'injecter l'en-tête `Metadata: true` requis par l'IMDS Azure (`169.254.169.254`) et de récupérer un jeton Azure AD, correspondant à CWE-918 (Server-Side Request Forgery). `fixed.rs` bloque explicitement l'adresse de métadonnées en plus de la whitelist générale et du filtrage des plages privées/link-local, et ne transmet plus aucun en-tête contrôlé par l'utilisateur à la requête sortante, empêchant toute injection de `Metadata: true`. Cette correction applique la recommandation de `rules/remediation/metadata-azure.md` : filtrer explicitement `169.254.169.254`, ne jamais laisser une requête sortante contrôlée par l'utilisateur définir librement les en-têtes HTTP, et appliquer le moindre privilège sur l'identité managée.
