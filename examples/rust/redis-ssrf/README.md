# SSRF ciblant Redis

`vulnerable.rs` construit la chaîne de connexion Redis à partir d'un hôte et d'un port entièrement fournis par l'utilisateur, sans whitelist, permettant à un attaquant de rediriger la connexion vers n'importe quelle instance Redis interne généralement dépourvue d'authentification, ce qui correspond à CWE-918 (Server-Side Request Forgery). `fixed.rs` fige l'hôte et le port Redis dans des constantes de configuration serveur, ajoute un mot de passe obligatoire (`requirepass`/ACL) même en réseau interne, et valide strictement le format de la clé de cache demandée. Cette correction applique la recommandation de `rules/remediation/redis-ssrf.md` : activer l'authentification et les ACL Redis même en réseau interne, et restreindre strictement les destinations autorisées pour toute connexion contrôlable indirectement par l'utilisateur.
