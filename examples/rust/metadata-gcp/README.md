# SSRF vers le service de métadonnées GCP

`vulnerable.rs` laisse l'utilisateur définir librement l'URL et les en-têtes HTTP d'une requête sortante sans filtrer la plage link-local ni le nom d'hôte de métadonnées, ce qui permet, sur GCE/Cloud Run avec un compte de service attaché, d'injecter l'en-tête `Metadata-Flavor: Google` et d'atteindre `metadata.google.internal` pour récupérer un jeton IAM, correspondant à CWE-918 (Server-Side Request Forgery). `fixed.rs` bloque explicitement l'adresse `169.254.169.254` et le nom d'hôte `metadata.google.internal` en plus de la whitelist générale et du filtrage des plages privées/link-local, et ne transmet plus aucun en-tête contrôlé par l'utilisateur, empêchant l'injection de `Metadata-Flavor: Google`. Cette correction applique la recommandation de `rules/remediation/metadata-gcp.md` : filtrer explicitement l'adresse et le nom d'hôte de métadonnées, appliquer le moindre privilège sur le compte de service, et ne jamais laisser l'utilisateur définir les en-têtes HTTP sortants.
