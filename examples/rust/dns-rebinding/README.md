# DNS Rebinding (contournement de filtre SSRF)

`vulnerable.rs` valide l'IP d'un hôte via une première résolution DNS puis effectue la requête HTTP réelle séparément, laissant `reqwest` re-résoudre le nom au moment de la connexion : si l'attaquant contrôle un domaine dont la réponse change entre les deux résolutions (TOCTOU), la validation initiale est contournée, ce qui correspond à CWE-918 (Server-Side Request Forgery). `fixed.rs` résout le DNS une seule fois, valide l'adresse IP obtenue contre les plages privées/loopback/link-local, puis épingle cette IP via `Client::builder().resolve(...)` pour forcer la connexion réelle sur l'adresse déjà validée (DNS pinning), tout en conservant le nom d'hôte pour SNI/TLS. Cette correction applique la recommandation de `rules/remediation/dns-rebinding.md` : ne jamais valider un hôte via une résolution DNS distincte de celle réellement utilisée par la connexion sortante.
