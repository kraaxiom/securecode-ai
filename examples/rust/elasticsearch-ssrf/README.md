# SSRF ciblant Elasticsearch

`vulnerable.rs` construit l'URL d'un proxy de recherche à partir d'un hôte Elasticsearch entièrement fourni par l'utilisateur, sans aucune whitelist, permettant à un attaquant de rediriger le service vers n'importe quel hôte interne, ce qui correspond à CWE-918 (Server-Side Request Forgery). `fixed.rs` fige l'hôte du cluster dans une constante de configuration serveur jamais dérivée d'une entrée utilisateur, ajoute une authentification obligatoire (`basic_auth`) même en réseau interne, valide strictement le nom d'index, et transmet la requête de recherche via des paramètres structurés plutôt que par interpolation brute dans l'URL. Cette correction applique la recommandation de `rules/remediation/elasticsearch-ssrf.md` : ne jamais laisser l'utilisateur contrôler l'hôte/port du cluster de recherche et activer l'authentification/le contrôle d'accès sur l'API Elasticsearch même en réseau interne.
