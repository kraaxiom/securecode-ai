# Agent Hijacking

La version vulnérable laisse un agent LLM exécuter directement les étapes de son plan, y compris des outils à fort impact comme l'envoi de paiements ou la suppression de comptes, sans aucune validation métier indépendante ni confirmation humaine, ce qui permet à un contenu externe ayant influencé la planification de détourner l'agent vers des actions irréversibles (CWE-1427, Improper Neutralization of Input Used for LLM Prompting). La version corrigée sépare la couche de décision du LLM de la couche d'exécution : les outils à fort impact exigent une confirmation humaine explicite, chaque étape passe par une validation métier indépendante du modèle avant exécution, et toutes les décisions et actions sont journalisées pour permettre un audit post-incident.
