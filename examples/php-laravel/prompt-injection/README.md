# Prompt Injection

La version vulnérable construit le prompt envoyé au modèle par simple concaténation de chaîne entre le prompt système et l'entrée utilisateur, sans séparation structurelle des rôles, et exécute directement les appels d'outils générés par le modèle sans aucune validation applicative indépendante, ce qui empêche le modèle de distinguer structurellement les instructions du développeur de celles potentiellement injectées par l'utilisateur (CWE-1427, Improper Neutralization of Input Used for LLM Prompting). La version corrigée utilise les rôles structurés de l'API (system/user) pour maintenir une frontière de confiance explicite, valide chaque appel d'outil contre un schéma strict avant exécution, applique le principe du moindre privilège en limitant les outils exposés par défaut, et exige une confirmation explicite pour les actions à fort impact.
