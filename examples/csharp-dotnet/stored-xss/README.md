# Stored Cross-Site Scripting (CWE-79)

La version vulnérable affiche le nom d'affichage et la biographie d'un utilisateur, tous deux issus de la base de données, directement dans le HTML du profil sans encodage. Comme ces valeurs sont persistées, toute charge malveillante enregistrée une seule fois par un utilisateur reste active et s'exécute pour chaque visiteur consultant ce profil par la suite, sans qu'aucune interaction supplémentaire (comme cliquer un lien piégé) ne soit nécessaire — ce qui en fait la variante la plus critique du XSS, pouvant toucher des administrateurs consultant les profils. La correction encode systématiquement `DisplayName` et `Bio` via `HtmlEncoder.Encode` au moment de l'affichage, garantissant que le contenu stocké est toujours rendu comme texte inerte plutôt que comme HTML actif. Si du contenu riche (mise en forme) devait un jour être autorisé dans la biographie, il faudrait le sanitiser avec une bibliothèque HTML dédiée avant stockage, en plus de l'encodage à l'affichage.
