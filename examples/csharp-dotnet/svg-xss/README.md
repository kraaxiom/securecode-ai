# XSS via SVG (CWE-79)

La version vulnérable accepte un fichier SVG uploadé, le stocke sous son nom d'origine, puis le sert tel quel avec `Content-Type: image/svg+xml` depuis le même domaine que l'application. Le format SVG est un document XML pouvant contenir des éléments actifs (`<script>`, attributs `onload`/`onerror`, schémas `javascript:`), qui s'exécutent dans le contexte d'origine de l'application dès que le fichier est ouvert directement dans le navigateur. La correction ajoute une étape de sanitisation XML (`SvgSanitizer.Sanitize`) qui retire les balises `<script>` et les attributs d'événements ou schémas dangereux avant l'écriture sur disque, renomme le fichier avec un identifiant généré côté serveur pour éviter toute manipulation du chemin, puis sert le fichier avec l'en-tête `Content-Disposition: attachment` afin de forcer le téléchargement plutôt que le rendu inline. En production, héberger ces fichiers depuis un sous-domaine dédié sans cookies de session apporterait une couche de défense supplémentaire.
