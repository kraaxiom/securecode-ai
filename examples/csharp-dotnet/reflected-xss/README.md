# Reflected Cross-Site Scripting (CWE-79)

La version vulnérable insère le paramètre de requête `q` directement dans le HTML de réponse par interpolation de chaîne, sans jamais passer par un mécanisme d'échappement. Comme cette valeur provient de la query string et est renvoyée immédiatement dans la réponse, un attaquant peut piéger une victime avec un lien contenant une charge malveillante dans le paramètre `q` : le script s'exécute dans le navigateur de la victime dès l'ouverture du lien, sans persistance côté serveur. La correction encode systématiquement `q` (et chaque valeur dérivée de la requête, comme les noms de produits filtrés) via `HtmlEncoder.Encode` avant insertion dans le HTML, ce qui neutralise les caractères spéciaux (`<`, `>`, `"`, `'`) et empêche toute sortie du contexte texte prévu. Cette approche reproduit l'échappement automatique qu'offrirait un moteur de templates comme Razor lorsqu'il n'est pas contourné par `Html.Raw`.
