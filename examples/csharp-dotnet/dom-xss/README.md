# DOM-based Cross-Site Scripting (CWE-79)

La version vulnérable construit une page HTML dont le script inline concatène directement le paramètre `q` dans une affectation `var query = "{q}";`, puis réinjecte cette valeur dans le DOM via `innerHTML`. Un attaquant peut fournir une valeur qui referme prématurément la chaîne JavaScript et le tag `<script>`, injectant ainsi du markup ou du code interprété par le navigateur — la vulnérabilité se joue entièrement côté client, une fois la page chargée. La correction sérialise `q` en JSON échappé via `JsonSerializer` avant de l'insérer dans le script (empêchant toute sortie du contexte chaîne), puis remplace le sink dangereux `innerHTML` par `textContent`, qui traite systématiquement la valeur comme du texte inerte plutôt que du HTML actif.
